# Evidence Sources and Verification Scope

Beyond the Alert contains a maintained implementation, original documentation and diagrams, explicitly synthetic examples, and a supplied lab artifact collection. These materials have different evidential roles.

## Lab artifact collection

The main README integrates 14 diagrams, screenshots and a reported comparison chart selected through `Bible for Artifacts and info.MD` from `Final Copy of Artifacts`. Published PNG bytes match the supplied files; existing provenance labels remain intact. The collection contains prior display-name/date adjustments and is not presented as newly captured event evidence or a complete correlated execution trace. Source labels inside images are preserved rather than renamed to fit the repository title. [Artifact guide](artifacts.md) and [integrity manifest](../assets/lab/provenance.json).

The supplied 15-row CSV supports a clearly labeled reported-evaluation section. Its measurements and ratings are not transferred to the maintained implementation. The legacy workflow/source code remains separate from the maintained code.

## Maintained implementation examples

All five example inputs are labeled synthetic. Their JSON and HTML outputs are reproducible from maintained source. Screenshots in the code walkthrough show those actual generated views and do not imitate running product interfaces. Fixture timestamps and identifiers are synthetic data; test-run timestamps come from executed validation commands.

## Video and future service evidence

The explanation video is conceptual and uses a fictional analyst. The current README player uses the user-provided V2 MP4, uploaded unchanged; [video-source.json](../assets/video-source.json) records its SHA-256, duration and attachment URL. The original MP4 is a separate version with SHA-256 `f33721525db75db053b20cb97fa56ae01195a09f6da27c6f4dc17068b346eb29`. Neither version establishes service execution, timing or containment.

For future service evidence, record collection method, UTC time, source versions, run IDs, integrity hashes, transformations and access restrictions. Preserve originals and redact secrets transparently. Distinguish a configured capability, an attempted operation, an accepted receipt and a confirmed security outcome.
