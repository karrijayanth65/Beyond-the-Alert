# Contributing

Open an issue describing the analyst problem and expected behavior. Use synthetic examples and exclude credentials, internal host data and personal information. Keep changes focused and explain what evidence supports the result.

Use a `codex/` branch for automation changes or another descriptive branch for human work. Run build, demo, tests and check commands from the README. Include failure-path coverage when changing service boundaries. Regenerate the n8n export from maintained source rather than editing embedded validator code by hand.

Describe actual verification in the pull request. Mark service integration work pending until receipts and a correlated trace exist. Preserve evidence provenance and required licenses. Documentation and visuals must not imply an unperformed live run.
